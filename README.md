# SecHub Noir v4

Статический русскоязычный портал по Linux, сетям, OSINT и кибербезопасности. Разработан для публикации на GitHub Pages.

## Что нового в v4

- Полностью обновлённая главная страница с технической редакционной композицией.
- Четыре стеклянные навигационные карточки неправильной формы: Каталог, Мини-инструменты, Правила и Автор. Нажатие открывает соответствующий раздел сайта.
- Frosted-glass оформление применяется также к каталогу, инструментам, правилам, панели навигации и блоку автора.
- Карточки реагируют на указатель мягким бликом и подъёмом; анимации не используют сторонние библиотеки.
- Робот SecHub находится внутри главного экрана и следит за курсором только пока открыт раздел «Главная». При переходе в другой раздел слежение останавливается и координаты очищаются.
- Робот не использует камеру, микрофон, сенсоры, сеть или хранилище.
- Учитывается системная настройка `prefers-reduced-motion`.
- Сохранены каталог из 44 ресурсов, поиск, категории, локальная оценка тестовой строки пароля и разбор URL.
- Добавлены Open Graph метаданные и `.nojekyll` для публикации.

## Запуск локально на Arch Linux

```bash
cd ~/Downloads/sec-hub-noir-v4
python -m http.server 8000 --bind 127.0.0.1
```

Открой `http://127.0.0.1:8000`.

## Публикация на GitHub Pages

1. Создай репозиторий на GitHub, например `sec-hub`.
2. Загрузи **содержимое** папки `sec-hub-noir-v4` в корень репозитория: `index.html`, `style.css`, `app.js`, `assets/`, `.nojekyll`, `README.md`.
3. Открой **Settings → Pages**.
4. В разделе **Build and deployment** выбери **Deploy from a branch**.
5. Выбери ветку `main` и папку `/ (root)`, затем нажми **Save**.
6. Дождись публикации GitHub Pages и открой показанный GitHub Pages URL.

`index.html` лежит в корне и открывается по умолчанию. Все локальные пути относительные (`./style.css`, `./app.js`, `./assets/mark.svg`), поэтому проект подходит для адреса вида `https://<username>.github.io/<repository>/`.

## Примечание о заголовках безопасности

Meta CSP в `index.html` ограничивает источники скриптов, стилей, изображений, сетевые соединения, фреймы, объекты и отправку форм. GitHub Pages не применяет файл `_headers` как конфигурацию HTTP-заголовков; он оставлен для хостингов, которые поддерживают такой формат, например Cloudflare Pages. Поэтому для GitHub Pages важны CSP meta-тег, локальные ресурсы, отсутствие сторонних скриптов и безопасные ссылки.

## Безопасность и приватность

- Нет backend, аналитики, трекеров, внешних библиотек, сторонних шрифтов и API-запросов.
- Данные каталога выводятся через DOM API и `textContent`; `eval()` и `innerHTML` не используются.
- Внешние ссылки создаются только для HTTPS и открываются с `noopener noreferrer` и `no-referrer`.
- Локальная оценка пароля — приблизительная эвристика, не проверка утечек. Используй только вымышленный пример.
- Разбор URL не открывает адрес и не делает сетевой запрос; результат не гарантирует безопасность сайта.
- Робот получает события указателя только в главном разделе. Движение не сохраняется и не передаётся.

## Обновление каталога

Ресурсы находятся в начале `app.js` в объекте `RESOURCES`. Добавляй проверенные официальные адреса и описания; перед публикацией тестируй ссылки вручную.
